# 涉税裁判文书公开库（cncases/cases · 102G 全量包）价值研判

> 研判日期：2026-10-10。研判对象：社区流通的裁判文书网全量备份（macrodatas.cn 原始包 / `810air.torrent` 公开 BT 种子 / amakerlife 94.3G 磁力备份），用途：为本项目税务案例库（现有 4,221 件行政类 md，RAG/微调）补齐裁判文书类（税务行政诉讼、逃税/虚开/骗税刑事判决）。
> 调研方式：GitHub API（cncases/cases 全部 issue）、种子文件直接解析（bencode）、caseopen.org 在线服务实测（curl + 网页读取）、WebSearch 公开报道。**未下载 102G 数据。**
> 标注：凡 **[实测]** 为本次直接验证；引用均附来源。查不到的事项在第 8 节明说。

---

## 1. 结论速览

### 建议：**不下载 102G 全量包**；改走「caseopen.org 在线 API 定向导出涉税子集」路线；全量包仅作兜底预案（条件触发才启用）。

**一句话理由：涉税子集只有约 5.6 万件（占全库 0.04%），却要为它付出 102G 下载 + 200G 数据库 + ≥320G 磁盘 + 数小时转换的代价；且公开种子数据只到 2021 年（无 2022-2024），而 caseopen.org 在线服务跑的是作者私有扩充库（到 2024-10）、原生支持「案由+年份」字段检索与万人分批含全文 JSON 导出——同样的涉税数据在线上版本更全、获取成本低三个数量级。**

| 维度 | 结论 |
|---|---|
| 日期分布 | 公开种子 1985-2021；作者私有库到 2024-10；2025-2026 全网无批量来源 |
| 增量机制 | **无**。原始源（马克数据网）页面已下架，作者增量靠私有渠道不公开分发 |
| 涉税子集体量 | 约 5.5-5.6 万件（虚开 3.88 万 + 发票类犯罪约 1 万 + 税务行政 4,716 + 逃税 2,286 + 骗税 783），解压后估计仅数百 MB |
| 全量下载成本 | ≥320G 磁盘、BT 种子健康度存疑（2025 年已有人报无速度）、Windows 转换程序有崩溃前科、源头已下架 |
| 在线导出成本 | 约 6-10 次 API 请求（每次 1 万条含全文 JSON），几小时内完成，零磁盘开销 |
| RAG 价值 | 旧判决（≤2021）对「构成要件/争点类型/司法认定逻辑」仍有效力；对「当前执法口径」确有时效缺口——但该缺口本项目已由 4,221 件 2021-2026 行政案例覆盖，裁判文书恰好补的是另一维度（司法审查结论），互补而非重复 |

## 2. 日期分布证据（核心）

### 2.1 全库裁判年份分布（作者库，含其私有增量，截至 2024-10）

来源：cncases/cases issue #164《Data Exploration》（作者 cncases 本人 2025-12-12 发布的 `judgment_date` 分组统计，即 caseopen.org 在线库的真实分布）：

| 裁判年份 | 文书量（行） | 裁判年份 | 文书量（行） |
|---|---|---|---|
| ≤2012（累计） | ≈ 1,001,297 | 2018 | 19,194,074 |
| 2013 | 1,424,120 | 2019 | 23,259,734 |
| 2014 | 6,933,704 | **2020（峰值）** | **23,701,977** |
| 2015 | 9,581,646 | 2021 | 16,642,628 |
| 2016 | 12,325,959 | 2022 | 9,217,363 |
| 2017 | 16,576,873 | 2023 | 5,920,651 |
| | | 2024 | 3,252,710（止于 10 月；10 月仅 43,354 件，7/8/9 月为 32 万/26 万/17 万，断流趋势明显） |

- 全库各 `case_type` 合计 ≈ 1.49 亿行（民事 90,694,186 + 执行 42,387,269 + 刑事 11,140,620 + 行政 3,237,237 + 其他）。注意：马克数据网原始包自称「8500 万+文书」——**作者库 = 马克数据网 + 其私有增量合并，多于公开种子**（issue #159 用户问「为什么我下的种子数据没你的多」，作者让其邮件联系）。
- **2022+ 占比仅 12.4%**（1,839 万 / 1.48 亿）；**2013-2021 占 87.5%**。
- 与官方口径互证：人民日报 2024-01-30 引《中国经济周刊》统计——文书上网量 2021 年降 29%、2022 年降 46%、2023 年降 64%，**其中行政诉讼文书降幅最大**；央视网 2024-02-27 最高法回应称上网文书从 2020 年 1,920 万件降至 2022 年 1,040 万件。作者库年份分布（2020 峰值 2,370 万 → 2023 年 592 万）与官方降幅曲线一致，说明该库忠实反映了文书网公开收缩后的存量。

### 2.2 公开种子（810air.torrent）的实际数据范围：**1985-2021，无 2022-2024**

[实测] 直接解析 GitHub 仓库内 `810air.torrent`（969,863 字节，bencode 解析，创建于 2023-12-15）：

- 共 41 个文件，总计 101,319,452,767 字节 ≈ 101.3G（与 README「102G」相符）。
- 结构 = `{年份}年裁判文书数据.zip` × 37（1985→**2021** 止）+ 3 个「不良资产知识星球」推广文件 + `数据说明.txt`（84 字节）。
- 关键年份 zip 体积：2019 年 14.0G、2020 年 26.3G、**2021 年 9.1G（最后一个年份文件）**。
- 旁证：issue #217（2026-05-22）用户：「这个数据是21年的，有更新最新的数据吗？」；issue #113（2025-06-07）用户问「您那有 21 年 10 月之后的更新数据吗」，作者答：「**我另有数据源，整合了马克数据网的数据。最新数据是 2024 年 10 月**」——增量数据在作者私有库（caseopen.org 在线跑的就是它），**不随种子分发**。
- amakerlife 94.3G 磁力备份（2023-12）：README 原话「可惜了，本来是挺好的政策，**24 年就关了**」——同代备份，量级更小。

### 2.3 涉税案由的年份分布：无法直接查到，只能按全库比例估算

- caseopen.org 的 SQL 探索接口（sql.caseopen.org，issue #166）与搜索接口本次全部被 Cloudflare「Just a moment」挑战拦截 [实测 2026-10-10]，**无法按「案由 × 年份」交叉统计**（这是本次调研明确的「查不到」项）。
- 按 2.1 的全库比例做保守估算（假设涉税案由年份分布与全库一致；注意行政类文书 2021 后降幅大于均值，故对「税务行政管理」此估计算偏乐观）：
  - 公开种子内的涉税文书（≤2021）≈ 总量 × 87.5%；
  - 仅存于作者私有库的 2022-2024 涉税文书 ≈ 总量 × 12.4%；
  - 2025-2026 = 0（全网无来源）。
- 涉税行政诉讼的第三方旁证：锦天城《大数据下 1990-2024 年度全国税务行政诉讼案件实证分析》（2025-12，筛得 3,909 份）与 icourt《2023 年中国税务行政诉讼大数据分析报告》（2024-09）：2015-2020 高位、**2021 年起跳水至最低、2022 低位、2023 略回升但仍处低位**——跌幅直接归因于文书网上网率下降，而非真实案件量变化。

## 3. 增量机制：没有

1. **原始源已下架** [实测]：macrodatas.cn 文章页 `https://www.macrodatas.cn/article/1147471898` 现标题为「**数据已下架**」，评论区止于 2024-02。源头不再供应。
2. **作者私有增量不公开**：issue #113/#159 中作者对「更多数据」的答复一律是「请发邮件至 contact@caseopen.org」或指向 issue #135——#135（2025-08-13）明确开出共享条件：**为社区部署一个境外公共在线查询实例（≥500G SSD/4 核 8G/全文本索引/高可用），即可共享数据**。即：想拿 2022-2024 增量，要么邮件谈合作，要么帮作者扛镜像。
3. **文书网本体不可作为补新渠道**：2021-07 起整改收紧、2023-12 转建法院内部「全国法院裁判文书库」、2024 年检索大幅受限、2026-01「法官隐名」风波（BBC 中文 2026-01-16；最高法审管办回应承认「错误隐名、显属不当」并要求整改）——公开上网量骤减且质量受损，逆向爬取价值极低且本项目已有结论「不自爬」。
4. 官方替代品「人民法院案例库」（rmfyalk.court.gov.cn）：经最高法审核的精选案例，量小、无批量接口，适合做评测集而非语料库。

## 5. RAG 价值分析（对应本项目：企业税务风险应对、稽查应对、争议分析）

### 5.1 ≤2021 旧判决仍有参考价值的部分（税法框架稳定层）

- **刑事构成要件与辩护逻辑稳定**：刑法第 205 条（虚开增值税专用发票罪）、第 201 条（逃税罪，含「经税务机关下达追缴通知后补缴不予追究」的行政前置程序）、第 204 条（骗取出口退税罪）的构成要件自 2011 刑法修正以来未变；判决书中反复出现的争点——有无真实交易、资金回流、善意取得虚开发票、单位犯罪与责任人员划分、自首立功与补缴退税从宽——**认定逻辑与证据审查方法至今通用**。
- **行政诉讼争点类型稳定**：税务行政管理案由下，争点集中于税款追征期（3/5 年）、滞纳金性质与上限、稽查局职权范围、处罚裁量（是否过罚相当）、纳税担保与复议前置程序、举报奖励——这些程序性框架在《税收征管法》层面长期稳定（征管法 2001 修订沿用至今，2024-2026 处于修订进程中）。
- **说理文本的训练价值**：法院「本院认为」部分是高质量的法条适用+事实涵摄文本，恰是现有 4,221 件行政文书（税务机关单方认定）所缺的**司法审查视角**。

### 5.2 已变/正在变的部分（引用旧判决需加时效标注）

- **两高《关于办理危害税收征管刑事案件适用法律若干问题的解释》（法释〔2024〕4 号，2024-03-20 施行）**：重新界定了虚开犯罪界限、骗税「假报出口」情形、逃税数额标准等——**2024-03 前的虚开/逃税/骗税判决在定罪量刑标准上部分被取代**，RAG 检索必须按判决日期与该解释做分层提示。
- 《行政处罚法》2021-07 修订施行（处罚程序、主观过错要件）→ 2021 前行政处罚程序合法性判断标准有变。
- 《发票管理办法》2023 修订、数电票（全面数字化电子发票）2021 试点后铺开 → 2021 前判决的证据形态（纸质票、金税三期比对）与当前金税四期/数电票执法环境差异明显。
- 小规模纳税人免征额、留抵退税政策（2022 大规模实施）等优惠口径多次调整 → 直接引用旧判决中的税额计算不可靠，需配本项目法规库做时效校验。
- 征管法修订（进行中）：落地后追征期/滞纳金等条文可能调整，库需保留修订标注能力。

### 5.3 缺近年文书对「应对当前执法口径」的影响 + 与现有库的互补性

- 影响真实存在：2022-2026 恰是八部门联合打击骗税、金税四期深度应用、数电票全网的执法环境剧变期，**新近判决最能反映法院对新执法手段的态度**（如数电票虚开的证据认定）。公开种子（≤2021）覆盖不到；作者私有库也只到 2024-10；2025-2026 全网无解。
- 但本项目现有 4,221 件（2021-08→2026-09 的税案通报/处罚公示/典型案例，见 SOURCES.md）**恰好覆盖了「当前执法口径」这一时间窗**——行政实践侧是新的，司法判例侧是旧的，两者互补而非同质。
- 组合后的 RAG 问答形态：「稽查中常见的虚开认定要件与抗辩（判例支撑，≤2021）+ 近两年稽查/处罚实践重点（4,221 件，2021-2026）+ 现行法条与 2024 司法解释（法规库）」——三源引用在检索层按「时点+性质」打标即可控制幻觉与过时风险。
- 体量匹配：5.6 万件涉税判决 → 清洗后估计 2-4 万条高质量 md（去除裁定书/简式文书/重复案号），与现有 4,221 件行政案例合成后总量 ≈ 3-5 万件，量级完全可控。

## 6. 替代方案对比（不下载全量包的三条路）

### 方案 A（**推荐**）：caseopen.org 在线 API 定向导出

[实测+源码验证] 能力与路径：

- 检索语法（作者帮助文档 static/help.txt，与线上 help.txt 同源）：支持字段 `cause:`（案由）、`year:[N TO M]`（年份范围）、`judgment_date`、`case_type`、`court`、`legal_basis`、`full_text:` 等的组合布尔查询（tantivy 语法）。
- **导出 API 含全文**：`GET /api/search?search=<查询>&offset=<N>&export=true` 返回 JSON，`cases[]` 每条含 `full_text` 全文 + 案号/法院/案由/裁判日期/当事人/法律依据等全部字段（controller.rs `CaseData` 结构验证）；HTML 导出仅元数据+240 字预览，**走 /api/search JSON 才带全文**。
- 每请求上限 10,000 条（`export_limit`），涉税全量 ≈ 5.6 万件 → **约 6 次×每案由 1-2 次请求**，总量个位数到十余次请求。
- **数据比公开种子多 2022-2024 三年**（在线库=作者合并库，截至 2024-10）。
- 风险与合规：(1) Cloudflare 挑战拦截脚本访问 [实测：curl/网页读取工具全部收到「Just a moment」，仅真实浏览器会话可过] → 需人工浏览器会话分批导出，或极低速真实浏览器自动化；作者 #135 正在找镜像托管者，单人低频取数（十余次请求、避开高峰）属服务明示支持的导出功能，但**不要做高频抓取**（个人服务器）；(2) 服务为作者个人维护，存在下线风险 → **拿到涉税子集后本地即持有目标数据，服务存亡不再是依赖**；(3) 文书原文再分发仍是灰色地带，沿用本项目「只发脚本/元数据、不发原文」纪律。

### 方案 B：只下 BT 包部分卷 —— **否决**

见 4.3：涉税分布横跨全部年份卷，选择性下载无实质节省，且仍需 320G 管线。

### 方案 C：等官方/其他渠道 —— 只作补充

- 人民法院案例库（最高法审核精选）：量小质高，抓「税务」主题做评测集（几十件）即可，不构成语料来源。
- 文书网本体：维持「不自爬」结论（2024 起大幅受限 + 2026 隐名风波 + 历史瑞数/sojson 反爬）。
- 商业库（北大法宝/威科/CnOpenData/DevnorsAI SDK）：付费，可作少量补漏对照，不入库。

### 兜底预案（触发条件才启用全量下载）

若出现以下任一情况且确需全库：caseopen.org 长期不可用/CF 完全封锁 + 社区出现新镜像（如 #135 找到托管方后数据更开放）——届时按 WSL2 + ≥320G 磁盘执行 cncases 管线（convert 在 Linux 下已验证可跑完 8,500 万条），避开 Windows 原生 convert.exe 的 zip-rs 崩溃风险。

## 7. 建议执行路径（方案 A 具体步骤）

1. **备选查询集**（浏览器登录 caseopen.org 后逐个执行，注意查询语法标点必须英文半角）：
