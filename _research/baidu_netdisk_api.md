# 百度网盘 AI Agent 文件上传 API 可行性调研报告

> 调研日期：2026-10-10
> 调研目的：评估百度网盘作为本项目（55,518 件中国法律法规文件，md/docx，总量数 GB）云端上传/分发通道的可行性，并与腾讯 IMA 知识库通道对比。
> 调研方法：官方文档站 sitemap 全量抓取 + 官方文档原文逐页核读 + GitHub 仓库元数据/README 核查 + 中英文网络检索。所有关键结论均标注来源；查不到的信息在文末"未查明事项"中明示。

---

## 0. 结论速览

| 调研项 | 结论 | 置信度 |
|---|---|---|
| 是否有官方文件上传 API | **有**。预上传 precreate → 分片上传 superfile2 → 创建文件 create 三步流程；另有单步上传接口（小文件一次请求完成）；支持秒传（block_list/content-md5） | 高（官方文档原文核读，文档更新于 2026-09-09） |
| 是否有文件列表/建文件夹/下载直链 | **有**。文件列表 method=list / listall、创建文件夹 method=create (isdir=1)、下载经 filemetas 拿 dlink（支持 Range 断点续传）、分享链接（新版服务） | 高（官方文档原文核读） |
| 个人开发者能否申请 | **能（截至本报告日）**。个人实名认证后可创建 1 个应用；应用用途选【个人使用】免审核、限 10 个授权用户。注意：约 2025 年曾"暂停个人创建应用"，2026-07-14 官方文档删除了暂停表述（即已恢复），政策存在反复 | 中高（官方"创建应用"文档 2026-08-03 版原文 + 更新日志 2026-07-14 条目交叉印证；申请页为 JS 动态渲染，未能最终截图确认页面入口状态） |
| 企业资质是否必需 | 非必需（个人通道存在），但企业认证（1~3 个工作日、需营业执照）配额更高（最多 10 个应用、正式配额白名单） | 高 |
| 关键限制 | ① 应用只能读写 `/apps/{appname}` 沙箱目录（2026-06-03 后新建的应用强制）② 未过审核的应用接口频率 **10 次/小时**、限 10 用户 ③ 单文件 ≤4GB（普通用户）④ 分片 ≤1024 片 ⑤ 上传能力需在应用中开通（否则报 31024） | 高（官方"权限与配额"文档 2026-07-03 版原文） |
| 正式配额数值 | **未公开**。已过审核应用为"按需分配（白名单制）"，具体 QPS/日调用次数无公开数字；上传类接口官方表述"仅对异常行为进行相应限制" | 中（官方文档明示白名单制但无数值） |
| 官方 MCP Server（Agent 路径） | **有**（github.com/baidu-netdisk/mcp，2025-07 发布）。但**远程 SSE 模式不含上传工具**，上传必须走本地 stdio 模式；个人"限时体验"用的是官方共享公共 Token（会不定期更换、禁用于生产） | 高（官方 README 原文核读） |
| 第三方工具（bypy/BaiduPCS-Go） | bypy（8.6k star，走官方 OAuth，限 `/apps/bypy`，2025-04 后未更新）；BaiduPCS-Go qjfoidnh fork（5.7k star，**2026-09 仍活跃**，走 BDUSS+STOKEN Cookie 模拟，账号线缆风险自担） | 高 |
| 对本项目最可行路径 | **官方 REST API + 自写/参考批量上传脚本**（有现成参考实现 jiuhespec/baidu-netdisk-batch-uploader，2026-08，基于官方 API、SQLite 断点续传）；不建议 Cookie 模拟类工具做生产通道 | 高 |
| 与腾讯 IMA 对比 | IMA 仍是首选（有 RAG 语义检索、配额已知 1.3 万次/日）；百度网盘适合做**冷备份/公开分发第二通道**（容量免费、无公开的每日上传次数上限、有分享直链），但无 AI 查询层 | 高 |

**一句话结论：百度网盘有完整、官方、活跃维护（文档 2026-09 仍在更新）的文件上传 API，个人开发者当前可以申请；但对 5.5 万文件量级，"个人使用"免审核应用的接口频率档位未公开，需先小规模实测，若被按"未审核档 10 次/小时"限流则该通道不可行，需走应用上线审核或企业认证。**

## 1. 官方开放平台 API 清单（调研项 1）

### 1.1 平台与文档入口

- 开放平台官网：<https://pan.baidu.com/union>（申请接入：<https://pan.baidu.com/union/apply>）
- 技术文档中心：<https://pan.baidu.com/union/doc/>（Astro Starlight 站点，含 sitemap，本次通过 sitemap 全量核对了文档结构）
- 接口基座：百度 OAuth 2.0（openapi.baidu.com）+ xpan/pcs REST 接口

### 1.2 上传能力（全部核自官方文档，更新时间 2026-09-09）

上传分三个阶段，依次依赖：

| 阶段 | 接口 | 方法与 URL | 说明 |
|---|---|---|---|
| 1. 预上传 | precreate | `POST https://pan.baidu.com/rest/2.0/xpan/file?method=precreate` | 提交 path/size/isdir/block_list（各分片 MD5 的 JSON 数组，32 位小写）、可选 content-md5/slice-md5；返回 uploadid 与待传分片序号。**若云端已有同内容文件可直接秒传**（return_type 标识） |
| 2. 分片上传 | superfile2 | `POST https://<UPLOAD_HOST>/rest/2.0/pcs/superfile2?method=upload&type=tmpfile` | 上传域名必须先经"获取上传域名"接口动态获取；≤4MB 文件一次调用即完成 |
| 3. 创建文件 | create | `POST https://pan.baidu.com/rest/2.0/xpan/file?method=create` | 携带全部 block_list 合并文件，秒传场景此步直接返回成功 |
| 单步上传（小文件） | upload | `POST https://<UPLOAD_HOST>/rest/2.0/pcs/file?method=upload` | 一次 HTTP 请求完成上传+建文件，官方注明"存在能力与大小限制，通用场景建议分片流程" |
| 获取上传域名 | locateupload | `GET https://d.pcs.baidu.com/rest/2.0/pcs/file?method=locateupload&appid=250528` | 返回 host/servers/bak_servers/quic_servers，禁止写死域名 |

文档真实 URL（sitemap 核对）：
- 能力说明：<https://pan.baidu.com/union/doc/基础网盘服务/上传/能力说明/>
- 预上传：<https://pan.baidu.com/union/doc/基础网盘服务/上传/预上传/>
- 分片上传：<https://pan.baidu.com/union/doc/基础网盘服务/上传/分片上传/>
- 创建文件：<https://pan.baidu.com/union/doc/基础网盘服务/上传/创建文件/>
- 单步上传：<https://pan.baidu.com/union/doc/基础网盘服务/上传/单步上传/>
- 获取上传域名：<https://pan.baidu.com/union/doc/基础网盘服务/上传/获取上传域名/>

官方还提供 **Go 版上传 SDK**（uploadsdk.tar.gz，含 precreate/upload/create 三阶段 demo）与 Python/Java/cURL 官方示例。

### 1.3 文件管理与分发相关接口（与本需求"按文件夹组织 + 分发"直接相关）

- 创建文件夹：`POST /rest/2.0/xpan/file?method=create`（isdir=1）
- 文件列表：`GET /rest/2.0/xpan/file?method=list`（分页）；递归列表 `method=listall`
- 文件搜索：关键词搜索 / 语义搜索（`搜索文件关键词搜索`、`搜索文件语义搜索` 文档）
- 管理文件：copy/move/rename/delete（`method=filemanager`）
- 下载：`GET /rest/2.0/xpan/file?method=download` + filemetas(dlink=1) → dlink（302 跳转，支持 Range 断点续传）
- 文件分享（新版服务，2026-09-16 旧版下线）：创建分享链接、获取分享下载地址、分享转存等——**适合做对外分发通道**
- 网盘容量查询：获取网盘容量信息接口

**对本项目的含义**：md/docx/pdf 均为普通文件类型，无类型限制（仅 App 端普通用户不能传视频）；几 KB~几 MB 的文件全部落入"单分片"场景，每个文件最少 3 次 API 调用（precreate + 1 次 superfile2 + create），或用单步上传降为 1~2 次。

## 2. 接入门槛（调研项 2）

核自官方"接入流程"（2026-08-10 版）、"创建应用"（2026-08-03 版）、"企业开发者认证"（2022-03-24 版）文档：

1. **注册百度账号 → 登录开放平台 → 同意《开发者服务协议》→ 实名认证**。
2. **认证分两档**：
   - 个人实名认证：身份证姓名+号码即可；**完成后可创建 1 个应用**；
   - 企业开发者认证：需企业负责人实名、营业执照影印件、统一社会信用代码等，**1~3 个工作日人工审核**，最多可创建 10 个应用。
3. **应用用途两选一**（创建应用时的关键选项）：
   - **【个人使用】：免审核，应用创建后直接上线，限 10 个授权用户**；
   - 【公开发布】：需提交上线审核，通过后不限用户数、按审核内容开放正式配额。
4. 应用类型分软件/硬件/小程序三类；**小程序类需企业认证**。软件类即覆盖本需求（服务器脚本调用）。
5. 凭证：AppId / AppKey / SecretKey / SignKey；OAuth 授权码模式或简化模式获取 access_token（随 refresh_token，有效期 10 年，可长期无人值守刷新）。
6. **未发现"网址 ICP 备案"作为 API 接入硬性条件**的官方表述（仅需在控制台配置 redirect_uri 回调地址；个人脚本可用简化模式/本机回调，bypy 等项目即如此实践）。企业深度合作（生态签约）才涉及线下流程。

**重要波折（政策反复）**：约 2025 年开放平台曾公告"由于开放平台优化升级，暂停个人创建应用，具体恢复时间以官网通知为准"（第三方教程留档，explinks.com 2025-12），官方 MCP README 也写明"百度网盘开放平台目前仅限企业开发者注册调用"；但 **2026-07-14 官方更新日志记载：创建应用文档"删除'暂停个人创建应用相关'的表述"**，且现行文档（2026-08-03）恢复了"完成个人认证后可创建一个应用"的描述。即：**个人通道截至本报告日已恢复，但过去 18 个月内经历过关闭，长期政策稳定性存疑**。

## 3. 配额与限制（调研项 3）

核自官方"权限与配额"（2026-07-03 版）与"上传能力说明"（2026-09-09 版）：

| 维度 | 未通过/未提交应用上线审核 | 已通过应用上线审核 |
|---|---|---|
| 接口频率 | **10 次/每小时** | 按需分配（白名单制），逐接口说明 |
| 次数 | 按接口单独说明（付费/特殊接口固定额度） | 同左，可申请扩容 |
| 最大授权用户数 | 10 个 | 不限制 |
| 超限错误码 | 20011（用户超限）/ 20012（频率超限）/ 20013（无接口权限） | — |

**注意**：应用用途【个人使用】"免审核直接上线"，但官方未明确该状态对应上表哪一档配额——这是本次调研最重要的未决问题（见第 8 节）。上传能力文档另有表述："频次限制：开放平台仅对异常行为进行相应限制，不会影响正常使用"。

其他硬限制（上传能力文档原文）：

- **目录沙箱**：每个应用在网盘只能拥有 `/apps/{appname}`（用户视角为 `/我的应用数据/{appname}`）一个文件夹用于存储、上传、下载。**2026-06-03 之后创建的应用**，precreate/download/meta/move/filemanager/listall 等接口被强制限定在该目录内（越界返回 20011"路径不在允许访问范围内"）。对"按文件夹组织"的需求：可以在沙箱内自由建子目录树，**但无法写入网盘任意位置，也无法读取网盘已有其他文件**。
- 单文件大小：普通用户 **4 GB**、会员 10 GB、超级会员 20 GB；分片数 ≤1024（默认分片 4 MB → 4 MB×1024=4 GB 与单文件上限自洽）。
- 上传权限需开通：应用需在控制台接入"上传能力"，否则分片/单步上传返回 31024"没有申请上传权限"。
- 存储容量：无单独的"API 容量"概念，占用授权用户本人网盘容量（个人版免费容量随账号政策，可经"获取网盘容量信息"接口查询；具体免费额度数值本次未从官方渠道取得，不编造）。
- Token 有效期：access_token 较短（默认约 30 天，MCP README 明示），refresh_token **10 年**，适合脚本长期运行。
- 官方 MCP SSE 服务默认频控：20 次/10 秒（可作为"正式档大致量级"的旁证：≈2 QPS）。

## 6. 官方 MCP Server：Agent 专用路径（附）

官方仓库 README（核读原文）要点：

- 能力：用户信息、文件信息、**上传（file_upload_stdio / file_upload_by_url / file_upload_by_text）**、mkdir、文件列表、文件管理、分享链接等，覆盖 MCP 协议。
- **关键限制：远程 SSE 模式（`https://mcp-pan.baidu.com/sse?access_token=...`）不提供上传工具**（服务端无法读本地文件），**上传必须用本地 stdio 模式**（`uv run netdisk.py`，环境变量 `BAIDU_NETDISK_ACCESS_TOKEN`），或自己按第 1 节 REST 接口实现。
- SSE 默认频控 20 次/10 秒。
- Access Token：官方授权链接（Implicit 模式）获取，**有效期 30 天**，可用 refresh_token 刷新（有效期 10 年）。
- **个人"限时体验"通道使用官方共享公共 client_id（QHOuRXiepJBMjtk0esLhrPoNlQyYd0mF）与公共 Token，官方明示"密钥将不定期变更，请勿用于正式环境"**——适合 30 分钟打通 demo，不适合 5.5 万文件的生产任务。
- 上传默认落盘 `/来自：mcp_server` 目录（即官方应用自身的沙箱目录）。

## 7. 结论与建议（调研项 6）

### 7.1 路径排序

1. **首选（若继续用百度）：官方 REST API + 自建批量上传脚本**
   - 个人实名 → 创建 1 个软件类应用（用途【个人使用】，免审核）→ 控制台开通"上传能力" → OAuth 简化模式拿 token（脚本半自动）→ refresh_token 长期续期。
   - 实现可直接参考 jiuhespec/baidu-netdisk-batch-uploader（官方 API、断点续传、限流退避）或官方 Go SDK demo；自写 Python 约 150 行（precreate/superfile2/create 三函数 + 目录遍历 + 重试）。
   - 文件组织：在 `/apps/{appname}/` 下按 `law/行政法规/xxx.md` 重建目录树（先 mkdir 再传，或直接用 path 隐式建目录——precreate 需目录存在，官方流程为先创建文件夹）。
   - **先做 100 文件的小规模实测**：验证"个人使用"档的真实频率限制。若被 10 次/小时卡死（20012 错误），则必须提交应用上线审核申请正式配额，或放弃该通道。
2. **次选：官方 MCP stdio 模式**——仅当想在 Agent 框架内统一调用时使用；SSE 无上传，公共 Token 不可生产，仍需自建应用，实质是 REST 方案的封装，量大了反而多一层。
3. **不推荐：Cookie 模拟类（BaiduPCS-Go/BaiduPCS-Py）作为生产通道**——可用性最好但属灰色地带，账号风控与接口突变风险不可控，与本项目"稳定分发的严肃资料库"定位冲突。
4. **不可行场景**：若拒绝任何注册/认证，则百度网盘没有"零门槛"官方上传接口（公共体验 Token 除外）。

### 7.2 与腾讯 IMA 对比（针对本项目 55,518 件 / 数 GB）

| 维度 | 腾讯 IMA 知识库 | 百度网盘开放平台 |
|---|---|---|
| 上传配额 | 已知：1.3 万次 create_media/日 → 5.5 万件约 3~4 天 | **未知**：未审核档 10 次/小时（不可用）；正式档白名单制无公开数字；上传接口"仅限异常行为"（乐观但模糊）。**每文件 2~3 次调用 × 5.5 万 = 11~17 万次调用**，需实测 |
| 接入成本 | 已打通（现用） | 新增：实名认证 + 建应用 + 开上传权限 + OAuth 脚本，约半天~1 天 |
| 存储成本 | 知识库配额 | 占用百度网盘个人容量（免费额度内通常足够数 GB） |
| 检索/消费层 | **RAG 语义问答（核心价值）** | 无 AI 层；仅文件列表/关键词搜索/语义搜索（网盘侧），分发靠分享链接/直链 |
| 文件组织 | 知识库条目 | `/apps/{appname}` 沙箱内自由目录树 |
| 分发能力 | 私有知识库 | **强**：分享链接（新版服务）、dlink 直链、转存 |
| 政策风险 | 配额收紧风险 | 个人通道 18 个月内开关一次；目录沙箱化；115 前车之鉴 |
| 速率量级旁证 | 1.3 万/日 | MCP SSE 档 2 QPS ≈ 17 万/日（若 REST 正式档相近，则 1 天可传完；未证实） |

**最终建议**：
- **IMA 继续作为主通道**——它是唯一带语义检索的消费层，且配额可预期（3~4 天完成迁移完全可接受）。
- **百度网盘作为补充/冷备通道值得做**，定位是"公开分发 + 异地备份"，而非 IMA 的替代。行动项：① 个人认证建应用开通上传权限；② 用 100 个 md 文件实测频率档位；③ 若通过，跑批量脚本（预计 1~3 天完成 5.5 万件）；④ 失败（20012 频率墙）则评估是否值得提交上线审核，或直接放弃百度通道。
- 不用 Cookie 模拟工具做本项目生产通道。
