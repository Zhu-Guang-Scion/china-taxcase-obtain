# 沪深交易所上市公司税务公告（巨潮资讯通道）— 踩坑实录

> 2026-10-12 · R15 · adapter: `adapters/cninfo_taxcase.py`
> 背景：用户点名补充深交所/上交所税案。上市公司披露的《税务行政处罚决定书》《税务处理决定书》
> 《补缴税款公告》《税务事项通知书》等是富全文信源（违法事实+金额+处罚结果+公司应对），
> 且 2025-2026 新案占比高，正好补库内新案不足。

## 信源选择：为什么走巨潮而不是两所官网

| 通道 | 状态 | 结论 |
|---|---|---|
| 深交所 `POST www.szse.cn/api/disc/announcement/annList` | HTTP 500（channelCode/参数形态已变） | 本轮不修——巨潮等效覆盖 |
| 上交所 `query.sse.com.cn/search/getESSearch.do?sqlId=BS_GGLL` | HTTP 404（老 sqlId 废弃） | 同上 |
| **巨潮 `POST www.cninfo.com.cn/new/fulltextSearch/full`** | **可用** | 深交所旗下法定披露平台，沪深公告同源，PDF 直链无鉴权 |

巨潮 = 全市场法定信息披露的唯一聚合点，比两所各自官网覆盖更全（一家不漏），
且免登录、无限流挑战。**收沪深两所公告优先走巨潮。**

## 巨潮 fulltextSearch 接口的三个坑（实测）

1. **翻页参数是 `pageNum`，不是 `page`**——传 `page=2..11` 永远返回第一页
   （症状：翻 N 页去重后只有 10 条）。这是最隐蔽的坑，silent 无报错。
2. **`type:"shj"` 会把检索锁死在新三板/退市板块**（secCode 全是 8/4 开头）。
   网上流传的示例代码多带这个参数（"shj"疑为"三板+沪+京"）。**收沪深主板必须不传 type**，
   去掉后 603 沪市立即出现。
3. **`market` 参数无效**（传 szsh/szse 结果与不传一致）。市场过滤只能靠
   `secCode` 前缀自查：
   - 上交所：600/601/603/605/688/689/900（B股）
   - 深交所：000/001/002/003/300/301/200（B股）/420（老B转）
   - 其余（43/83/87/92/920 等）为新三板/北交所，本通道不收

其他细节：
- 标题级检索 `isfulltext:"false"` 只搜标题；`"true"` 是全文检索（会带进法律意见书
  等大量噪音——"偷税"全文命中 3,408 条但标题级 0 条，公司公告标题不用这个词）。
- 标题带 `<em>` 高亮标签需剥除；`announcementTime` 是**毫秒**时间戳。
- PDF 直链 = `http://static.cninfo.com.cn/` + `adjunctUrl`（如 `finalpage/2025-01-07/1222258397.PDF`），
  无鉴权无限流，走 polite_get 常规限速即可。
- 公告 PDF 均有文本层，pymupdf 直接抽（无需 MinerU OCR）；个别扫描件文本<80字
  会被 adapter 判失败落 progress 的 fail 记录。
